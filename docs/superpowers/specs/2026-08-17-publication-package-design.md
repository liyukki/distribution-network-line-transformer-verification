# 线变关系智能校验项目发布包设计

## 1. 目标与受众

本次收尾将当前工程整理为可公开访问、可独立复现、可用于电网/能源数字化实习展示的 GitHub 项目。主要受众包括：

1. 希望本地运行项目的本科生、面试官和工程开发者；
2. 希望理解线变关系校验问题、算法与实验边界的论文读者；
3. 希望核查结果来源、复现路径和工程质量的代码审阅者。

交付物不宣称已经使用真实电网数据、已经现场部署或达到生产精度。

## 2. 交付物

### 2.1 使用说明

创建 `docs/user-guide.md`，作为从安装到结果解释的完整中文手册，至少包含：

- 项目适用范围与合成数据声明；
- Windows、Linux 和 macOS 环境安装；
- 默认流水线、单阶段 CLI、报告生成和清单校验命令；
- Streamlit 看板启动方法、中英文切换及五个页面说明；
- 运行产物、关键字段、指标口径和证据包说明；
- 鲁棒性实验与三个教学 Notebook 的执行方法；
- 常见错误、排查顺序和安全边界；
- 面试演示建议与进一步开发方向。

README 在快速开始区链接该手册和论文，不复制整篇内容。

### 2.2 项目论文

创建以下文件：

- `paper/line-transformer-verification-paper.md`：论文 Markdown 权威原文；
- `paper/line-transformer-verification-paper.pdf`：面向下载和投递的排版成稿；
- `paper/references.bib`：可核验的参考文献元数据；
- `paper/figures/`：论文使用的静态图；
- `scripts/generate_paper_figures.py`：从公开权威证据生成结果图；
- `scripts/build_paper.py`：将 Markdown 和图表转换为 PDF。

论文采用中文技术论文结构：题目、摘要、关键词、引言、问题定义、数据与系统、方法、软件实现、实验设置、结果、鲁棒性与消融、讨论与局限、结论、参考文献、复现声明。

## 3. 论文论点与真实性约束

论文定位为“可复现的线变关系智能校验工程原型及失效边界研究”，贡献限定为：

1. 建立可控台账错误、噪声、缺失、时移和光伏扰动的合成实验链；
2. 实现残差相关、差分相关、滚动相关、事件匹配与有功功率相关的可解释融合评分；
3. 建立覆盖率门禁、保守判定、候选馈线排序和明确的不适用语义；
4. 建立 manifest、SHA-256、配置快照、公开证据包和全自动测试构成的复现闭环；
5. 通过 130 个鲁棒性与消融案例分析适用边界。

所有数值必须直接来自以下权威文件或由脚本确定性计算：

- `reports/metrics/default_summary.json`；
- `reports/metrics/robustness_aggregates.csv`；
- `reports/metrics/robustness_summary.csv`；
- `reports/metrics/robustness_experiment_manifest.json`；
- `reports/evidence/default_run/`。

默认结果必须如实报告：24 台配变、5 个实际台账错误、F1 为 0.167、PR-AUC 为 0.378、Top-1 修正率为 0.2、Top-2 修正率为 0.4。不得使用“准确率 90%”“工业级”“现场验证”等无证据表述。算法表现较弱时，解释其失效边界和后续改进方向，不删减负面结果。

## 4. 图表设计

论文至少包含四幅由脚本生成的静态图：

1. 系统数据流与证据链流程图；
2. 原始 Pearson 基线与增强方法的指标对比图；
3. 默认运行混淆矩阵；
4. 鲁棒性实验与消融结果图。

图表读取权威产物，不手工录入实验数值。PNG 使用适合 A4 PDF 的分辨率和中文字体；每幅图包含单位、图例、数据口径和来源说明。生成脚本不得改写权威输入。

## 5. 文献与引用

参考文献以一手论文和官方文档为主，覆盖：

- 智能电表电压相关性与配电网拓扑/变压器归属辨识；
- 异步配变监测数据的拓扑辨识；
- 含分布式电源、噪声和缺失数据时的局限；
- pandapower；
- Pearson 相关分析及项目实际使用的方法；
- 作为后续方向讨论的 DTW 与 Isolation Forest。

正文中只有实际实现的方法可以写入“本文方法”；DTW、Isolation Forest 和 GNN 只能作为未实现的未来工作。每条参考文献必须包含可核验 DOI 或官方页面，不引用搜索结果页，不虚构中文文献。

## 6. PDF 构建与视觉标准

PDF 使用仓库脚本可重复构建，输出 A4 版式，包含页码、目录、统一标题层级、图题、表题、公式和可点击链接。中文字体使用系统可用的开源或 Windows 中文字体，并在构建时检测；缺少字体时给出明确错误。

发布前将 PDF 渲染为页面图像，逐页检查：

- 无截断、重叠、乱码和空白异常；
- 图表清晰且不越界；
- 目录、标题、页码与参考文献完整；
- Markdown 与 PDF 的关键数值一致。

## 7. 测试与发布门禁

发布前必须满足：

- 文档测试与链接检查通过；
- 论文图表和 PDF 可从脚本重新生成；
- 默认公开证据包通过 manifest 哈希校验；
- 规范报告可由公开证据包逐字节复现；
- 130 个鲁棒性案例均完成且实验清单严格验证；
- 全量 pytest 通过且覆盖率不低于 90%；
- `src/`、`app/`、`tests/` 与新增脚本通过 Ruff；
- wheel 构建成功；
- Git 工作区无未提交文件。
